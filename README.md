# 东博会体验与提货协调

面向公众开放日的协调产品：统一管理展区、展位、展品、样机、讲解场次、体验资格、可售批次与提货点，让未来空间、AI商品和成员国展区同时开馆时，闭馆不留下争议。

## 运行

```sh
npm test
```

## 组成

- `fixtures/expo.json` — 虚构样例：未来空间展区（商业航天模型，仅展示）、AI商品展区（体验样机、现货与预售批次、分时价格版本、采集健康数据的手表）、成员国展区（气象设备预售）及两个提货点
- `src/catalog.js` — 目录资料加载与校验：销售方式（仅展示/现货/预售）、批次与展品一致性、引用完整性、按时刻取生效价格版本
- `src/sessions.js` — 扫码占位、授权核验、到场核验、设备停用与讲解改期的公平顺延
- `src/orders.js` — 接触留痕、下单绑定、批次扣减、合并付款、退款、分展区提货
- `src/venue.js` — 展区容量、等待时间估算、闭馆清场
- `src/ledger.js` — 展商对账
- `src/engine.js` — 统一入口：requestId 幂等、事件日志、断网同步与恢复
- `contracts/context.schema.json`、`fixtures/context.json`、`src/context.js` — 领域资料格式与样例（版本 2）

## 现场规则与实现对照

| 现场问题 | 协调规则 | 实现 |
| --- | --- | --- |
| 重复排队 | 每人同一时刻只持有一个有效时段，新扫码顶替旧时段；同场重复扫码返回原时段 | `scanSession` |
| 设备停用、讲解改期 | 已到场者优先，其余按占位先后，依次填满更晚场次，容纳不下的进入顺延场次 | `postponeSession`、`disableDemoUnit` |
| 未成年人、健康数据 | 体验类场次先核验监护人授权；采集健康数据的场次再核验健康数据授权 | `scanSession` + `grantAuthorization` |
| 样机当现货 | 仅展示品（模型）与样机不出售；现货、预售各自扣减对应批次 | `createOrder` + 目录校验 |
| 型号价格写错 | 订单必须引用本人接触记录，型号与价格版本以接触时为准，调价不影响已接触订单 | `touch` + `createOrder` |
| 跨区提货写错 | 提货点必须与商品所在展区一致，跨区订单分点各提各的 | `assignPickup` |
| 断网、重复扫码 | 每次操作携带 requestId 幂等；断网事件按发生时间排序落账，重复确认、冲突拒绝 | `syncOffline`、`ExpoEngine.recover` |
| 跨展位合并付款、退款 | 多订单一次付款全部校验通过才生效；退款释放批次且幂等，已提货不可退 | `pay`、`refund` |
| 闭馆清场 | 未核销时段过期、未支付订单取消并释放批次；已支付订单与待提货单保留 | `clearVenue` |
| 围观冒充订单 | 对账只含已完成体验与已支付订单，接触与排队列为非结算指标 | `statement` |
| 场馆调度 | 按展区真实在场人数卡容量，按场次排队与时长估算等待时间 | `enterZone`、`dispatch` |

## 一致性设计

- 每次变更都是一个携带 `requestId` 的操作，引擎记录事件日志（`exportEvents`），重复提交返回首次结果。
- `ExpoEngine.recover(资料, 事件)` 重放日志恢复现场，日志中的重复事件只生效一次。
- 手持设备断网期间积压的事件通过 `syncOffline` 补传：按发生时间（同刻按设备与序号）排序落账；时间早于观众现有时段的过期扫码被拒绝，不会顶替已生效时段。
- 操作返回的都是快照，调用方无法绕过规则直接改状态。
