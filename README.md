# 东博会体验与提货协调

定义公众开放日（未来空间、AI商品、东盟成员国展区）的展区、展位、展品、样机讲解场次、体验资格、可售批次、提货点协调，以及断网、退款、清场的一致性规则。

## 领域资料

- `contracts/context.schema.json`：共享资料格式（领域标识、版本、事实与约束）。
- `fixtures/context.json`：可公开使用的虚构上下文样例。
- `fixtures/expo.json`：协调产品的运行样例——3 个展区、6 个展位、8 件展品、8 个讲解场次、5 个可售批次、3 个提货点、10 名观众。不含真实个人信息、账号、密钥或凭据。

### 关键建模：展品 ≠ 商品

- 展位上的单元 `disposition` 只有 `model`（模型）、`prototype`（样机）、`display-only`（仅展示），**均不可直接销售**。商业航天模型、成员国气象样机都在这一层。
- 可售性只存在于 `batches`：`kind` 为 `spot`（现货）或 `presale`（预售），批次绑定价格版本与提货点。样机没有批次，"样机被当现货卖"在数据层即不成立。
- 订单对每件商品做**型号编码 + 价格版本 + 成交价**快照，避免事后改价或换货争议。

## 协调规则（`src/coordinator.js`）

| 场景 | 规则 |
|---|---|
| 扫码入场 | 每人全局仅一个有效时段（含候位），再扫他展被拒；取消/结束后才可再约 |
| 重复扫码 | 所有命令带幂等键，重复提交返回首次结果 |
| 资格核验 | 未成年人须监护授权、健康数据体验须健康授权；预约与入场两次核验 |
| 设备停用/改期 | 场次顺延、FIFO 队列原样保留，恢复后不插队、不丢号 |
| 超容量 | 超出进入候位，队首取消后按序递补 |
| 合并付款 | 一笔支付可跨展位覆盖多订单，对账按展商拆分 |
| 提货 | 默认按批次提货点；跨区须下单时显式改写到真实提货点，跑错点拒绝放行 |
| 退款 | 未提货可退、现货库存回补；已提货不退；操作幂等 |
| 断网 | 离线命令排队，恢复后重放；同批命令重复执行结果一致（见测试） |
| 清场 | 未支付订单释放库存、未入场预约取消、已付未提保留待提 |
| 场馆调度 | 依据容量与估算等待时间限流；围观人数单列展示，绝不计入体验或成交 |
| 展商对账 | 只确认真实入场人次、成交毛额、退款额与应收净额 |

## 代码结构

- `src/context.js`：上下文资料读取与必要字段检查。
- `src/expo.js`：展区资料解析与引用完整性校验（展区/展位/展品/场次/批次/提货点/观众）。
- `src/coordinator.js`：命令式协调核心。每条写命令形如 `{ id, type, at?, ... }`，`Coordinator.replay(data, commands)` 可由命令日志完整重建状态。
- `src/coordinator.js` 的 `venueView()` 与 `reconcile()` 分别服务场馆调度与展商对账。
